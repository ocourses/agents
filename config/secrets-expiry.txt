# (scripts/check-secrets-expiry.sh). Avertir AVANT la panne : un test de
# vivacité ne signale une clé morte que le jour où elle l'est déjà.
#
# GitHub n'expose pas l'échéance d'un PAT par l'API : ces dates-là sont saisies
# à la main (Settings -> Developer settings -> Personal access tokens), et le
# fichier ment dès qu'on oublie de le mettre à jour après une rotation.
#
# Les clés Albert, elles, sont vérifiables : GET /v1/keys/{id} renvoie le champ
# `expires`. Si le secret ALBERT_API_KEY est posé sur ocourses/agents, le job
# recoupe automatiquement les lignes ALBERT_API_KEY et signale tout écart —
# c'est Albert qui fait foi. D'où l'identifiant numérique « (#50717) » dans la
# dernière colonne : c'est lui qui permet d'interroger l'API.
#
# Format : <date ISO>  <dépôt>  <nom du secret>  <identifiant du jeton>
#   date  = AAAA-MM-JJ, ou "?" si l'échéance n'est pas connue (alors signalée
#           comme non renseignée, jamais ignorée en silence).
#   "#" pour commenter, une entrée par ligne.
#
# Rappel : chaque cours a SES PROPRES clés (valeurs distinctes sous des noms
# identiques), il n'y a donc pas de rotation groupée possible — chaque ligne
# se renouvelle indépendamment.
